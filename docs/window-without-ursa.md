# 独立窗口与 Ursa 移除说明

> 历史参考：记录当时的调研或诊断，可能包含已替换实现；现行规则与待办以 [资源键命名](resource-key-naming.md) 和 [优化任务清单](optimization-tasks.md) 为准。
Vhilz 核心库目前直接基于 Avalonia，不依赖 Ursa。是否提供 Ursa 集成后续再决定。

## 保留的能力

- `VhilzWindow` 直接继承 `Avalonia.Controls.Window`，`TitleBar` 直接继承 `TemplatedControl`。
- 标题栏三个内容槽统一为 `LeftContent`、`CenterContent`、`RightContent`；保留标题显示与对齐、标题栏背景、内外边距以及窗口按钮可见性设置。`CenterContent` 位于标题文字之后，不表示相对整个窗口居中。
- 明暗资源、窗口装饰模板和按钮动画继续使用 Vhilz 主题。
- 最小化、最大化、全屏、拖动、缩放和按钮可用性由 Avalonia 的窗口装饰体系处理。`CanMinimize`、`CanMaximize`、`CanResize` 仍使用框架属性。
- 自绘装饰与客户区重叠时，标题栏根据按钮实际布局宽度避让，保留应用设置的 `TitleBarMargin`。

## 接口变化

- `VhilzWindow` 与 `TitleBar` 不再能转换为 Ursa 类型。
- 移除 `OverlayDialogHost`、`PART_DialogHost` 以及模态状态报告附加属性。当前没有内嵌对话框宿主的替代实现；独立模态窗口使用 `ShowDialog<TResult>(owner)` 与 `Close(result)`。
- 移除 Ursa 的 `CanClose()` 扩展。同步关闭拦截使用 Avalonia `Closing` 事件并设置 `e.Cancel`。异步确认需由应用取消本次关闭、等待确认后重新请求关闭，并自行处理重复请求。
- 移除未被 Vhilz 模板使用的 `IsManagedResizerVisible`；窗口缩放交给 Avalonia。按钮可见性设置只影响自绘装饰，不改变平台原生按钮。

## 验证入口

### 全屏窗口动画

Windows 上通过公开的 Win32 消息钩子为全屏边界切换补充真实窗口尺寸插值，目标是接近最大化／还原的缩放过渡。它不是 DWM 系统动画的逐帧复刻；平台自身的最大化／还原路径仍优先。全屏状态、目标位置和恢复矩形仍由 Avalonia 计算，不新增依赖。快速反向切换先结算平台恢复矩形，再从当前可见尺寸继续动画；隐藏窗口时完成目标尺寸，关闭时解除钩子。

公共 Token `Vhilz.Window.FullscreenTransition.Duration` 默认 `220 ms`，`.Easing` 默认 `CubicEaseOut`，每次切换读取当前资源，可在应用或窗口资源中覆盖。时长设置为零可关闭插值；同时尊重 Windows 的“最大化和最小化时动态显示窗口”系统设置。此动画与全屏顶边标题栏的展开动画独立。macOS、Linux 保持平台原生切换，尚未验证其动画一致性；跨屏 DPI 切换也待实机检查。

全屏顶栏的展开、收回与正文避让由同一高度驱动，包含顶栏上下外边距，沿用 Reveal 的时长与缓动 Token。框架默认立即隐藏浮层，因此窗口在共同视觉宿主观察指针事件（不消费事件），在收回期间保留浮层，直到高度归零才隐藏；退出全屏或隐藏窗口时立即清理。Windows 在退出全屏按钮（客户区）与关闭按钮（原生非客户区）之间移动时，也可能发出宿主 `PointerExited`。此时事件坐标仍位于顶栏内，必须依据同一坐标边界判断，不能仅凭退出事件启动收回。该模板部件的高度由窗口独占，使用 `SetValue` 写入基础目标；不能在 Transition 运行中使用 `SetCurrentValue`，后者会覆盖动画优先级的当前值而保留旧基础目标，导致动画结束跳回零、布局重新触发展开。真实 Win32 指针回归曾捕捉到浮层保持可见但正文避让从 32 归零，修复后基础目标稳定为标题栏高度，实际高度连续插值。Headless 的单次展开检查未捕捉该时序，因此同时保留真实指针回归。

### 人工视觉检查

执行 `dotnet run --project Vhilz.Avalonia.Demo`。若已有 Demo 或设计器占用输出文件，关闭相关进程后再构建，或使用独立的 `--artifacts-path` 构建并运行该目录内的 Demo。

在 Demo 中切换明暗主题，并检查：

1. 缩窄窗口、切换最小化与全屏按钮显隐，标题栏右侧内容应避让窗口按钮。
2. 拖动、双击、最大化、还原和全屏；检查按钮悬停、按下、禁用及窗口失焦颜色。全屏时客户区标题栏收起，鼠标移到屏幕最顶端后，全屏栏横向展开，四周通过 `Vhilz.Window.FullscreenTitleBar.Margin` 保留 2 单位间距，以 `Vhilz.Window.FullscreenTitleBar.Reveal.Duration` 和 `.Easing` 控制向下展开，正文按同一高度同步避让。移出时按同一动画高度收回顶栏和正文，动画完成后隐藏浮层；收回途中重新进入顶栏范围可从当前高度反向展开。退出全屏、隐藏窗口或首帧前移出时直接结算。标题栏空白区域不可拖动，退出按钮不受进入按钮显隐设置影响。也可按未被内容控件消费的 `Esc` 退出全屏。
3. 勾选“取消关闭请求”后关闭窗口应被取消，取消勾选后应正常关闭。
4. 打开模态窗口，确认或关闭后主窗口应恢复交互，并显示返回状态。
5. Windows 上对比最大化／还原与进入／退出全屏，观察放大缩小是否连贯、是否闪跳；快速反向切换后检查恢复位置和尺寸，再从最大化状态进入全屏检查。明暗主题各检查一次。系统关闭窗口动画时应直接切换。
6. 从正文缓慢移到最顶边，再在展开过程中缓慢向下移动；快速移出再移入，连续重复至少十次。观察首次唤出与后续唤出是否同样连续，正文与顶栏是否始终相隔 2 单位，收回是否有连续动画、结束后是否无残留空白；检查顶栏上方及左右各 2 单位间距。展开后在退出全屏与关闭按钮之间缓慢往返、停留在边界，顶栏应保持展开；再移到正文，确认正常收回。明暗主题都需实际观察，视觉效果仍待验收。

### Windows 原生回归检查

`dotnet run --project Vhilz.Avalonia.Win32.SmokeTests -- <报告文件绝对路径>` 会在交互式 Windows 桌面自动打开并关闭独立测试窗口，并移动系统指针完成顶栏检查（结束后恢复指针位置）；请在运行期间避免操作鼠标或切换窗口。退出码为 `0` 表示通过，`1` 表示失败，非 Windows 返回 `2`。项目复用 Demo 的桌面依赖，不加入普通 Headless 测试流程。设置环境变量 `VHILZ_REVEAL_ONLY=1` 可仅运行顶栏回归。

检查明暗主题下的正常往返、快速反向、最大化往返、隐藏重现及动画中关闭；以零时长为平台基线对比最终状态和恢复矩形，正常往返还要求原生矩形出现多个中间帧。系统关闭动画时检查直接切换，不修改系统设置。该检查只确认状态和几何，不能证明动画观感正确。

顶栏回归在明暗主题下各执行十次真实指针慢速移动、快速移出再移入，断言展开高度不倒退、收回产生中间帧且高度不反弹、表面与正文始终相隔底部外边距、收回后无空白，并检查默认四周间距。每次展开还在退出全屏和关闭按钮之间穿越四次，断言顶栏保持完全展开；明暗主题合计八十次穿越。此项关闭独立的窗口缩放插值以隔离顶栏动画，窗口缩放仍由上述场景覆盖。

Headless 回归测试覆盖结构、绑定、按钮空间避让、关闭取消及模态返回；不构成视觉验收。材质、动画、平台原生交互和最终布局仍待实际运行验收，macOS 与 Linux 尚未验证。
