# F01 — 共享资源与视觉基线协调

阶段：P0 首轮准备，之后按实际消费者逐次处理。执行者为集成人或被单独授权的资源负责人；两者同时存在时也只允许一人写共享字典。

先读 [执行约定](../work-contract.md)、[资源键命名](../../resource-key-naming.md)、[资源字典设计](../../resource-dictionary-design.md) 和 [已确认决策](../../optimization-tasks.md)。状态只在 [领取记录](../claims.md) 维护。

## 可写文件

- `Vhilz.Avalonia/Themes/Resources/Tokens.axaml`、`Light.axaml`、`Dark.axaml`。
- `Vhilz.Avalonia/ResourceKeys.cs`。
- `docs/components/delivery/F01.md`：语义资源申请与决定，不另建第二套长期 Token 规范。
- 资源相关设计文档仅在规则实际变化且已讨论后更新。

集成人负责生产主题/样例的加载入口；组件模板仍由各自任务负责人修改。本卡不得直接替他们批量修模板。

## 首轮完成条件

1. 从当前字典和 ResourceKeys 核对现有资源、明暗键与类型；辨认 Button 的实际使用值及“仍为候选”的尺寸。语义键方向、现有时长档位等已确认事项不重复征求确认。
2. 为 P1 第一批领取任务提供可复用资源列表和缺口处理方法，不预建所有 shadcn 变体和一整套未使用尺寸档位。
3. 明确选中/强调、错误/危险、弹层、焦点/边框、输入高度/间距各用途是否已有资源。缺项只在消费者具体提出后登记名称、用途、类型、明暗候选及覆盖方式；尚未确认的全局档位/强调色保留候选身份并安排用户观察。
4. 首轮已能支撑领取者区分“复用现有资源”和“提交申请”，即首轮准备完成；不要求一次决定所有未来颜色或尺寸。后续申请按单独里程碑进入领取记录，不长期占用其他任务的代码权限。

## 每次资源接入的完成条件

- 相同用途只有一个语义来源；不存在仅因文件不同而复制的同值别名。
- 跨主题值进入 Tokens，随主题变化值同时进入 Light/Dark，键和类型相同；C# 常量同步。
- 模板消费方式可支持要求的主题切换与应用覆盖；需要验证时优先复用现有 ResourceDictionaryTests/WindowPaletteTests，强度遵循执行约定。
- 若改变已有 Token 的含义或值，列出实际消费者，先处理受影响组件；不能认为没有文本冲突就不影响旧界面。
- 资源与组件在同一集成基线构建，界面效果仍交由用户验收；没有实际用户确认就不升级为“已确认的全局视觉规范”。
