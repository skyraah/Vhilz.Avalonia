# C16 — Kbd

阶段：P3；预估风险：低。状态和负责人只在 [领取记录](../claims.md#c16) 维护。先读 [执行约定](../work-contract.md)，不要修改其他卡的文件。

## 目标与实现边界

键帽与快捷键序列的展示，按平台显示由应用提供的键名。

shadcn 目录对应：[kbd](https://ui.shadcn.com/docs/components/base/kbd)

- 通用前置：[F00](F00.md) 基线/Demo 协议可用；[F01](F01.md) 首轮资源契约可用。
- 组件硬依赖：[N02](N02.md)。依赖已集成且入口稳定后可编码；最终验收使用共同基线。
- 决策或交接：先确定最小公开用法；新类型/属性/事件及交互变化按 AGENTS.md 讨论后实施。
- 先检查本仓库已有控件与官方基件；设计组合优先于新增类。

## 必须保留或先确定的契约

非交互展示、长键名和多键布局；不注册全局快捷键。

## Demo 与可观察结果

Ctrl+K、组合键、长键名、明暗、行内对齐。

所有适用场景同时具备明暗主题；悬停、按下/选中、禁用和键盘焦点使用真实操作观察。未适用状态写“不适用”及原因，不人为给纯展示控件制造交互。默认外观、快速状态切换和应用覆盖沿用执行约定。
