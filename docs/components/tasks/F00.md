# F00 — 工作基线与 Demo 接入

阶段：P0，串行前置。执行者为集成人。任务状态只在 [领取记录](../claims.md) 维护。

先读 [执行约定](../work-contract.md)。本卡先解决并行交付的入口，不实现一批新控件，不迁移生产项目架构。

## 当前事实与目标

当前 Button、窗口、Token、ResourceKeys、Demo 等存在未提交改动，Demo 主要示例在 MainWindow。先确定可共享基线，再提供稳定的独立示例入口。不能把当前工作区直接当成所有新 worktree 自动具备的内容。

## 可写文件

- `docs/components/claims.md`：唯一领取与状态记录。
- `docs/components/delivery/F00.md`：基线清单、交接与宿主协议。
- `Vhilz.Avalonia.Demo/Catalog/ComponentCatalog.cs`、`ComponentCatalogWindow.axaml` 与 `.axaml.cs`：计划新增的内部 Demo 宿主与顺序登记表。
- `Vhilz.Avalonia.Demo/MainWindow.axaml` 与 `.axaml.cs`：在交接既有改动后增加进入组件目录的入口，保留已有窗口/图标/Button 示例。
- `docs/components/work-contract.md`：只有实际入口与约定不同才更新运行说明。

其他项目/公共文件的变化需先明确为什么当前入口无法完成最小接入；不为了本任务调整生产资源结构或公开控件命名空间。

## 执行步骤与完成条件

1. 读取 git 状态，标记当前工作文件与负责人可知的所有权；选择当前变更保留、交接及工作树起点。完成条件：新领取者能取得同一明确快照，且现有文件没有被重置/遗漏。Git 提交仍需明确授权。
2. 建立一个 Demo 目录窗口，由集成人维护显式登记表。每个登记项至少具备任务 ID、显示名和创建 Sample 的入口；各任务只提交自己的 UserControl，不修改登记表。完成条件：两个独立样例可按 ID 切换，样例卸载不会残留状态或订阅。
3. 工具区复用现有局部 Fluent 方式；目标预览区域加载正式 VhilzTheme，防止 Fluent 掩盖目标控件未实现状态。保持库“不自动加入回退主题”的现状，改变该策略另行讨论。
4. 预览支持明暗切换、可调整尺寸与真实键盘/指针操作；先接现有 Button 作为宿主验证，不迁移所有 MainWindow 内容。完成条件：Sample 类型/命名空间/登记格式写入交付包，后续任务可按模板提交。
5. 构建通过，若运行环境允许实际打开 Demo 检查登记与切换；否则记录阻断，不能将宿主标为已可运行。此为局部 Demo 组织改动，不默认增加整套测试设施。

## 串行边界

同一时刻只有一个集成人编辑 Catalog、总表、公共字典和项目配置。工作树隔离解决文件互踩，顺序接入解决公共资源与加载顺序冲突。并行任务仍需遵守文件和选择器所有权。
