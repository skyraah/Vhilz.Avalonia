# 组件任务执行与并行协作约定

本文用于执行 [组件建设表](README.md) 中的任务。先读仓库 [AGENTS.md](../../AGENTS.md)，再读本文件和领取的任务卡；只在任务需要时打开其依赖卡及研究资料。本文是协作方案，不表示目录中计划的控件或 Demo 宿主已经实现。

## 1. 领取与基线

1. 查 [领取记录](claims.md)。集成人一次只分配一个任务给一个负责人，记录负责人、工作目录、基线、依赖版本、交付位置。人和 AI 使用同一规则。任务卡是规格，领取记录是状态的唯一来源。
2. 多人并行使用各自独立工作树/检出和输出目录。需要包含未提交工作时，由 F00 明确交接哪些文件和内容；不能直接从远端默认分支开工后宣称包含当前 Button/窗口实现。不得自动提交、推送来解决基线问题；沿用用户对 Git 的授权边界。
3. 领取以集成人在唯一共享领取记录确认占用为准；各自在自己分支填写姓名不能形成互斥。跨设备不可见同一记录时由集成人顺序分配。任务表不是自动锁，也不能保证在同一目录同时运行的两个进程互不覆盖。
4. 普通任务领取后可以立即读源码、准备方案；进入编码前，F00 的基线和 Demo 约定必须可用，F01 已给出当前共享资源契约，任务卡的硬依赖已集成且具有稳定入口。依赖已构建并可使用即可开发；最终统一视觉验收等待依赖视觉基线确认。
5. 自研卡先完成最小用法、类型/属性/事件及交互方案；按 AGENTS.md 取得该任务所需授权后再实施。依赖新增、公共行为变化或回退策略变化也遵循已有决策规则，不因在任务表中出现就视为已批准。

同一负责人可以兼任集成人，但两种职责的文件权限仍分开记录。没有集成人时，先由执行者承担协调职责完成 F00/F01；不能绕过基线与共享资源交接。

## 2. 文件归属与接入

| 归属 | 可写内容 | 协作方式 |
| --- | --- | --- |
| 组件负责人 | 本卡列出的控件主题、自定义控件目录、独立 Demo 目录、必要且已选定强度的独立测试、`delivery/<ID>.md` | 在独立工作树内实现；其他任务的文件只读。任务完成一次交付整个包。 |
| 集成人 | `Themes/VhilzTheme.axaml`、`Themes/Resources/{Tokens,Light,Dark}.axaml`、`ResourceKeys.cs`、`Themes/Styles/CommonStyles.axaml` | 统一登记键、消除语义重复、加载控件与样式；不让各任务同时编辑这些文件。 |
| 集成人 | Demo 的 App/MainWindow/Program、F00 建立的 Catalog 宿主与目录、项目文件、依赖/构建配置、共享测试宿主/助手、领取记录与总索引 | 根据交付包顺序接入；需要决策的事项先完成讨论。 |
| 现有模块负责人 | `Controls/Windows/**`、`Platforms/**`、窗口主题、GeometryIcon/SvgIcon、GrassButton、当前未交接改动 | 本计划不会自动转交这些区域。确有需要时另行协调，而不是随某个普通控件任务顺手重构。 |

路径省略了 `Vhilz.Avalonia/` 前缀时指库项目。样例路径都在 `Vhilz.Avalonia.Demo/Components/<ID>/`，测试在 `Vhilz.Avalonia.Tests/Components/<ID>Tests.cs`；这些目录是任务输出规划，当前未创建实现。例外是 N01 在明确交接后继续维护现有 `ButtonTests.cs`。

即使 Git 没有文本冲突，也要检查：两个字典是否定义相同 `x:Key`/类型主题；一个选择器是否影响另一个控件；是否改写共同 Token 含义；是否占用相同全局事件/管理器；模板是否直接引用兄弟任务的私有资源。文件不重叠只是第一层隔离。

### 最小接入包

组件负责人在 `delivery/<ID>.md` 填写 [交付模板](delivery-template.md)，至少包括：

- 实际改动文件与基线，依赖使用的版本/快照；类型主题键及选择器作用域。
- 需要进入主题入口的 **精确 URI**、资源字典或 Styles 类型、加载顺序要求；类型键和命名主题的关系。
- 共享资源申请：键、CLR/AXAML 类型、用途、已有近义键、明暗候选、消费位置、是否对应用公开、对应 ResourceKeys 常量位置。没有资源申请就明确填“无”。
- Demo 完整类型名、入口显示名与组别；默认显示哪些状态、如何触发其他状态。
- 构建/测试实际结果、用户待观察项目、已知限制和平台未验证范围。

集成人先处理依赖与共享资源，再接入字典、Demo 和必要的测试宿主调整。集成后把准确基线返回负责人，负责人在最终组合上完成受影响的检查。**只写出 AXAML、没有实际接入 VhilzTheme 和 Demo 的任务，状态最多是“待集成”。**

资源缺失时可以继续结构设计，但不要在正式模板里以同义硬编码资源兜底，或把调试用临时资源当作已交付契约。需要运行的候选资源由集成人接入审阅基线，状态保持“视觉待验收”。

## 3. 视觉与资源约束

本项目沿用 [资源命名](../resource-key-naming.md)、[资源宿主与动态覆盖](../resource-dictionary-design.md) 和 [已确认决策](../optimization-tasks.md)。这些文件及实际字典是事实来源，本计划不重新发明一套 shadcn Token 或固定密度档位。

实现主题、class 变体或状态选择器时，读取 [AI 执行规范](selector-class-rules.md)；人类编写入口为 [指南与选择器语法速查](selector-class-guide.md)。选择器/class 规则以执行规范为唯一依据，交付包记录具体 class 契约和状态冲突，不在每张任务卡重复维护规则。

- shadcn/ui 用于核对组件用途、组成与场景，不强制照搬 Web 尺寸、颜色或 DOM 子组件 API。Vhilz 的方向仍是克制、清晰的 Linear 质感；普通控件简洁表面，玻璃主要用于有实际层次需求的容器。
- 先确定暗色，同时实现明色。交付一项任务就要能在两种主题中检查，不能留下“亮色后补”的实现。
- 先复用现有用途键。选择、强调、危险、错误、弹层、密度等缺少共同语义时，通过 F01 处理；同一需求只合并一次。尚未确定的圆角、间距、尺寸和强调色都保留候选身份。
- 状态层次区分常态、悬停、按下/选中、禁用、键盘焦点；错误、只读、展开、加载只在适用控件中出现。焦点与选中不可混为一种状态。
- 保留用户对控件属性、ControlTheme 和语义资源的覆盖；数值直接动态引用，不用静态别名模拟动态契约。单控件真正独立的参数允许局部键，由集成人登记；跨控件可复用参数在交付前进入公共 Token。
- 消费依赖的公开主题和属性。局部 Thumb/RepeatButton 等主题用明确命名并限定作用域；为一个模板需要而设置的 Button/TextBlock 样式不得泄漏到全局。
- 动效先稳定端点和反向连续性，再调整曲线；不为普通控件增加持续时钟或私有输入系统。玻璃采样只以应用视觉树为边界。

## 4. 从上游契约到最小实现

1. 读取当前依赖版本的官方控件源码/主题，列出真正依赖的模板部件、伪类、绑定、内容呈现器、焦点与键盘机制，记录源码版本和链接。任务卡中的属性例子不是完整上游契约清单。
2. 明确首个里程碑与完成范围。原生控件先保留类型/API，通过模板、资源与样式实现；确实缺少行为时，再提出最小扩展方案。
3. 先实现普通内容、关键状态和明暗切换；用 Demo 的真实动作产生状态，预览按钮要有计数、选中值或实际结果反馈。调试伪类仅为辅助，不能代替真实交互检查。
4. Demo 使用正式资源与控件接口。容器负责示例布局，不在 Demo 选择器里修复生产控件外观。提供一个不被局部 Fluent 掩盖的目标控件样例；工具区可按 F00 约定用现有局部 Fluent。
5. 检查旧实现和使用位置。已有 Button 是接续任务；其他未实现原生控件可以复用官方行为，但不能把 Fluent 回退截图标成 Vhilz 已适配。

## 5. 验证与完成标准

当前任务只是编写计划，没有替未来模块选择测试强度。执行时遵循 AGENTS.md：简单低风险样式改动可采用代码检查、构建和 Demo；完整控件或模块在编写/运行测试前说明建议覆盖与成本，选择轻量核心、适中回归或全面验证。已有该任务授权时不重复询问。等待答复时继续实现、构建与 Demo，不能自行扩大测试范围。

轻量建议只检查本卡的关键契约与明确风险，优先复用已有测试；不是逐个属性/伪类穷举。Headless 验证结构与行为，不证明材质、动画、对比度和真实平台正确。

在独立工作树内使用任务专属输出目录，示例（把 N02 换为自己的 ID）：

```powershell
dotnet build Vhilz.Avalonia.sln --artifacts-path artifacts/components/N02
dotnet artifacts/components/N02/bin/Vhilz.Avalonia.Demo/debug/Vhilz.Avalonia.Demo.dll
```

F00 如果调整 Demo 运行方式，应更新上述入口。不要用 `dotnet test` 整个解决方案作为每项任务的默认步骤。只有选择了相关测试且对应类存在时，才按其真实名称运行过滤用例，例如接续 Button 时使用现有 `ButtonTests`。测试结果、命令和运行限制放交付包，不按日期追加到设计规范。

| 状态 | 可核验的进入条件 |
| --- | --- |
| 未领取 | 尚无唯一负责人。依赖和决策条件见卡片；不表示马上可编码。 |
| 已领取·准备 | 已登记独立工作树和基线，正在读源码、定规格、确认必要决策。 |
| 实现中 | 依赖入口与共享资源契约可用，在本卡范围内编码。 |
| 待集成 | 独占文件与完整接入包可审阅；共享入口尚未进入目标基线。 |
| 已集成·待验证 | 生产主题、Demo 和资源已进入同一目标基线，等待最终组合构建/选定验证。 |
| 视觉待验收 | 构建及选定强度验证完成，Demo 可运行，人工观察项与未验证平台已记录。 |
| 已验收 | 用户确认本次范围的视觉/交互；记录确认来源与范围。首里程碑验收不代表后续里程碑完成。 |
| 受阻 | 明确缺少的依赖、授权或环境及解除条件；保留已完成成果，可继续不依赖阻断项的准备。 |

交付完成必须包括：正确加载的生产主题、适用的真实明暗状态 Demo、选定范围内的构建/测试结果、共享资源提取、依赖与入口登记，以及用户待验收项目。所有状态字段只在领取记录维护；某卡多个里程碑尚未完成时，不能把整卡标为已验收。

## 6. 可直接复制的领取指令

> 请领取组件任务 `<ID>`。读取 `AGENTS.md`、`docs/components/work-contract.md` 与该任务卡；通过集成人确认占用、基线和硬依赖，在独立工作树中只修改本卡授权文件。先列上游契约和必要决策，再完成该卡首个未完成里程碑。共享资源及 Demo/主题入口变更写入 `docs/components/delivery/<ID>.md`，交由集成人顺序接入。按照已授权测试强度验证，保留用户视觉验收步骤；不要提交、推送或修改其他任务文件。

领取者如果是 AI，使用其环境可用的工作树工具，不假设所有执行环境都具有 Codex 工具。需要人类决定的产品取舍与 API 方案应提供具体可审阅内容；例行可逆实现无需反复申请许可。
