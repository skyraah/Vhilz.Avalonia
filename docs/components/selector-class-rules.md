# 选择器与 Classes 执行规范（AI）

适用：编写、修改或评审本仓库 AXAML 的 `Selector`、`Classes`、嵌套 Style、ControlTheme
及相关状态代码。本文是项目规则的唯一依据；[人类指南](selector-class-guide.md)
提供语法解释与示例，不另设一套规则。资源与任务所有权仍遵循 [执行约定](work-contract.md)
和 [资源命名](../resource-key-naming.md)。

规范约束后续实现，不批量迁移现有模板或 class。已有行为或公开使用方式需要变化时，按 AGENTS.md 讨论。本次文档中的候选名称不是已经实现的变体。

## S1 — 修改前确定归属

1. 搜索目标主题、class 的定义/使用位置、状态生产者和任务卡。确认实际 `StyleKey`、使用的 Theme、部件名称和上游伪类；不能仅从
   CLR 继承或控件名称推断匹配。
2. 默认外观及状态放在所属控件的 ControlTheme 内；类型主题键只由该任务拥有。局部部件样式跟随同一模板，不写进全局
   CommonStyles。
3. 跨控件共享 class 只有在用途、属性和行为一致时才提交集成人处理。组件负责人不修改兄弟主题、Demo 工具区、共享入口或公共
   class 定义。
4. 提交包登记 class 契约、选择器影响范围和同属性状态冲突；完成条件是能指出每个选择器的宿主、目标及所有者，而不是只确认 AXAML
   能解析。

## S2 — 选择属性、Theme、class 还是伪类

| 意图                                        | 采用机制                                                                                |
|---------------------------------------------|-----------------------------------------------------------------------------------------|
| 值、选中、展开、禁用、只读、命令等行为/数据 | 现有公开属性及绑定；样式读取其真实状态。                                                |
| 同一模板下可复用的外观变体/内容呈现形式     | 已登记的 class；缺少契约时先登记再实现。                                                |
| 整套模板或特定部件的独立外观                | 命名 ControlTheme，必要时 BasedOn；一个控件一次选择一个 Theme。                         |
| 指针、按下、焦点、选择等控件固有状态        | 上游伪类或上游属性选择器。先核对该类型实际提供哪些状态。                                |
| 自定义控件固有状态                          | 控件内维护 PseudoClasses，按需声明 `[PseudoClasses]`；属于行为/API 设计，遵循任务授权。 |
| 应用条件决定的纯外观                        | `Classes.<Name>` 布尔绑定，只有一个状态生产者。                                         |
| 单实例布局差异                              | 控件公开属性或父布局；不为每个宽度/边距制造 class。                                     |

用 `IsEnabled`/`IsChecked` 等维护行为，不额外同步 `VhilzDisabled`/`VhilzChecked`。不向普通 Classes 集合塞 `:pressed`
等伪类。状态的来源必须唯一，不能同时由绑定和事件处理器切换同一个 class。

## C1 — Classes 命名与契约

- 新的组件专用 class 使用 **`Vhilz<控件或家族><用途>`**，PascalCase，仅字母和数字，例如候选 `VhilzButtonDestructive`
  。控件家族用于区别普通按钮与 CaptionButton，不以任务 ID 或页面名作为生产组件用途。
- 确有多个控件共同消费的 class 可申请短名 **`Vhilz<用途>`**，由集成人登记消费类型与相同语义；普通任务不得先占用
  `VhilzCompact` 等全局短名。
- Demo 自有 class 使用 **`VhilzDemo<任务ID><用途>`**，仅在该 Sample 作用域定义；不进入库，不能用它改生产控件内部视觉。
- 用途表达外观角色、内容呈现或行为中立的配置。禁止以 `Red`、`Radius8`、`Margin4`、页面/客户名称堆叠样式；密度值未确认时不得顺手确立全局
  Small/Medium/Large 档位。
- 不使用裸名 `Primary`、`Small`、`Active`、`Error` 作为新的库 class；不使用点、冒号、空格编码一个 class。`Vhilz.Button.Primary`
  是多个 class 条件的潜在歧义，不是资源键式命名。
- class 名区分大小写，大小写与拼写属于契约。上游 class 和现有已登记名称保持原样，不为满足新命名规则自动改名。

每个 class 的交付记录必须包括：名字、类型/家族、所有者、公开或内部、维度、默认值、互斥项、可组合项、状态生产者、作用域及实际
Demo。组件作者在自己的交付包登记；共享 class 的接入由集成人统一处理。

默认外观用“没有该维度 class”表达；有真实兼容或用法需要时才显式声明 Default 类。不要为每个组件预建完整变体集合。

## C2 — 多个 Classes 的顺序和互斥

静态 `Classes="..."` 按以下维度排列，缺少的维度跳过，同维度允许共存时按名称排序：

**语义角色 → 外观形式 → 密度 → 内容形式 → 布局方向 → 独立功能标记 → 内部投射状态**。

每个 class 只归一个维度。角色、外观、密度、内容形式、布局方向各维度默认最多一个；需要共存时在该控件契约中列出组合。功能标记也必须登记冲突。候选说明：Destructive
是角色，Outline 是外观，Compact 是密度，IconOnly 是内容形式；这些例子不代表库已有对应实现。

`Classes` 是集合，书写次序不改变优先级。互斥 class 同时存在属于调用错误，不能用“后一个 class
胜出”解决；通过调用方单一枚举/布尔条件保证互斥。现有调用冲突先反馈并修正调用，不静默删除调用方
class。若产品确实要支持冲突输入，先定义明确行为，再实现/验证。

条件 class 用 `Classes.<Name>` 管理成员；C# 只对自己拥有的成员执行 Add/Remove/Set。不要整体替换/清空 Classes 破坏消费者的其他成员。

## S3 — 选择器书写顺序

同一个目标段使用以下固定顺序：

`类型或 :is(类型) 或 ^ → #名称 → .Classes → [属性条件] → :伪类 → :not(...)`。

- 名称仅在确有精确定位需求时出现；Classes 按 C2 维度排序，属性条件按属性名排序。
- 多个正向伪类按“持续状态（checked/selected/expanded 等）→ pointerover → pressed → 焦点 →
  disabled”的类别顺序，同类按名称排序。这只是书写格式；不同控件不需要具备所有状态。
- `:not(...)` 在本目标段末尾，同类排除条件按名称排序。一个 `:not` 默认只放一个条件，复杂否定用连续 `:not`
  或重构条件，避免套用浏览器选择器语法。
- 组合关系在段之间写成一个空格、` > `、` /template/ `。AXAML 属性中的 `>` 统一写 `&gt;`。逗号分支之间一个空格，每个分支重复完整宿主和条件。
- ControlTheme 内的嵌套 Style 从 `^` 开始。`^:pressed` 是当前宿主的状态；`^ :pressed` 是后代，含义不同。不得机械插入空格。
- 选择器默认直接写在控件主题下。额外嵌套最多一层，用于减少重复且仍能清晰展开的局部规则；需要更深时先展开，消除“`^`
  到底指谁”的歧义。已有上游结构确有必要保留时在交付包说明。

格式统一的目的在于可读性与稳定 diff， **不会改变 Avalonia 的值优先级**。

## S4 — 作用域和模板边界

- `Button` 按 StyleKey 精确匹配；确实要包含派生样式类型时才用 `:is(Button)`，并核对受影响类型。不要以扩大匹配范围掩盖
  StyleKey/Theme 接入错误。
- 普通 Style 至少包含具体类型或组件拥有的宿主路径；禁止在库全局写 `.VhilzX`、`:is(Control)` 或任意 `Button TextBlock`
  作为广泛补丁。ControlTheme 的 `^` 已是明确宿主。
- 读取宿主状态后，优先设置宿主的公开可覆盖属性，再由 TemplateBinding 传给部件。只有部件独有的可见性、几何、动效等才直接命中部件。
- 进入自己模板时用 `^... /template/ 类型#精确名称`；名字保持上游必需 `PART_*`。一个无状态的部件默认值直接放模板属性/绑定中，避免依赖普通
  Style 去覆盖 Template 优先级。
- 目标为同一职责的一组部件时可使用受限 class/类型匹配，但必须列出命中的全部部件。若选择器越过子控件的第二层 `/template/`
  ，先检查是否应使用子控件公开属性或命名 Theme。
- 跨兄弟组件的私有部件、消费者提供的 Content/DataTemplate 和弹层视觉树不属于本卡可任意匹配的范围。空格和 `>` 匹配逻辑树，不保证穿越
  Popup；弹层应通过其已知宿主/展示器主题接入。
- 每个逗号分支都是独立选择器。主题中必须都带 `^`；样例：`^:pointerover:not(:disabled), ^:flyout-open:not(:disabled)`。

## S5 — 声明顺序和状态覆盖

资源字典按“所需局部资源/部件主题 → 主命名 ControlTheme → 基于主主题的类型键入口 →
Design.PreviewWith”组织；依赖定义在静态引用之前。Styles 根文件与 ResourceDictionary 分别接入，不能混用加载器。

主主题先写基础 Setter，Template Setter 放基础 Setter 末尾，再按下列阶段写 Style。 **阶段顺序优先于变体分组**；不要写完 A
的全部状态后再追加 B 的普通态覆盖它。

| 阶段 | 内容                                     | 同一阶段的顺序                                           |
|------|------------------------------------------|----------------------------------------------------------|
| 1    | 几何、方向、内容呈现等配置               | 基础条件在前，组合例外在后。                             |
| 2    | class 默认外观                           | 通用默认在前，组件专用在后，明确组合例外最后。           |
| 3    | 持续状态：默认操作、选中、不确定、展开等 | 基础状态在前，状态与变体组合在后。                       |
| 4    | pointerover                              | 普通态在前，选中/变体的悬停组合在后。                    |
| 5    | pressed                                  | 普通态在前，选中/变体的按下组合在后。                    |
| 6    | 只读/错误/忙碌等语义限制与提示           | 按该控件的同属性冲突表定义先后；不是全库固定严重性排序。 |
| 7    | disabled                                 | 明确保留选中/错误等信息的方式；交互状态不得继续染色。    |
| 8    | focus-visible 或明确需要的 focus-within  | 焦点层独立呈现；可交互控件的焦点可见样式排除 disabled。  |

相同阶段中同一目标属性不要隐式竞争。先用排除条件消除无需共存的状态，例如 hover 排除
pressed/disabled；需要“选中＋悬停”的情况写明确组合。并不要求复制一份完整矩阵，只为真实冲突定义规则。

每项交付只列实际冲突的属性：例如表面在“常态→选中→选中悬停→按下”如何变化，禁用后如何处理；错误边框和焦点轮廓是否用不同部件。焦点、错误、禁用不是谁最后写就全面清除前者的万能等级。Busy
也不自动意味着禁止所有操作，行为由公开属性决定。

## S6 — 按 Avalonia 优先级排查，不按 CSS 权重猜测

StyledProperty 常见优先级从高到低：

`Animation > LocalValue > StyleTrigger > Template > Style > Inherited > 默认值`。

条件 class、伪类和属性匹配通常进入 StyleTrigger；类型/名称本身不因更具体就变成触发级。同优先级还要检查作用域/样式接入位置，同一集合后声明通常胜出；不能把“最后一条”当作跨级覆盖规则。加更多
class、`#Name` 或伪类不会像 CSS 那样累计权重。

此顺序只比较 **同一对象的同一属性**。若 Button.Background 是局部值，但状态样式直接写
ContentPresenter.Background，两者不是同一对象，后者仍可能破坏应用预期。S4 要求通过宿主可覆盖属性传递，目的正是保留该契约。

排查顺序：实际 Theme/StyleKey → 是否命中与所在树 → 状态来源 → 最终对象/属性 → 值优先级 → 作用域与声明顺序 → 是否存在
Animation/Transition 的临时值。不能为“看起来没生效”直接 SetValue、扩大全局选择器或增加条件数量。

BasedOn 复用主题声明，不给选择器加权；StaticResource/DynamicResource 的差异是查找更新方式，不是值优先级。类变体定义、主题加载与资源覆盖是三件事，不能互相代替。

## S7 — 已有名称与迁移边界

| 名称                | 当前归属/消费者                               | 身份与写入方                                     | 本轮处理                                                              |
|---------------------|-----------------------------------------------|--------------------------------------------------|-----------------------------------------------------------------------|
| `VhilzCaptionClose` | WindowDecorations 中的 CaptionButton 命名主题 | 关闭按钮角色；库模板和对应 Demo 设置             | 保持既有拼写，只在该 Theme 内消费；不是所有 Button 的危险操作公共类。 |
| `VhilzInactive`     | TitleBar 及窗口标题文字命名主题               | 内部窗口激活状态投射；模板根据窗口 IsActive 绑定 | 保留既有机制；不是可由调用方随意设置的公共 Disabled/Muted 变体。      |

此表只列实际既有库名称。交付后集成人登记真正发布的新增名称和所有者；未实现候选只留在该任务交付包，不加入已支持列表。名称删除、改义、公开化或改为伪类都需先检查全部消费者，不在整理规范时自动实施。

## S8 — 提交前完成条件

- 选择器只触及本卡拥有的主题/部件；每个类有唯一生产者和已登记维度，无互斥项同时存在的示例。
- 书写顺序与阶段顺序符合 S3/S5；实际同属性冲突有明确组合或排除条件，不能只凭文字排序声称正确。
- 示例只使用已实现的类/键；候选代码块显式标注候选。应用显式属性覆盖与明暗切换路径可说明。
- 源码/主题改动按任务已选强度构建和验证；仅文档更改检查链接、事实和示例。轻量任务不因此新增全套选择器测试框架。
- 交付包记录 class、选择器边界及人工观察项；未经用户视觉确认不标记视觉通过。
